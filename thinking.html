内部发包流程构思

通过搭建自动化检查、分发、处理数据的内部系统，弱化对外包工具的依赖，构建一套即使外部零工具介入也能完整回收外包工作的稳健流程。

🎯 涉及环节🧩 功能模块🔄 完整流程📁 路径设计
✦

核心理念Core Philosophy

外包商素质良莠不齐，部分外包商几乎不依赖我方提供的工具也能按时完成任务。因此，从外部工具强约束的角度很难统一管控回传行为。

更稳妥的方式是：在内部搭建一套尽可能自动化的流程——自动检查、自动分发、自动处理数据，弱化内部效率压力。即使在完全不给外部提供任何工具、只提供制作数据的情况下，也能将外包工作完整地分发 → 回收 → 审核 → 发布。

部署 Linux

数据库模块

使用 PostgreSQL 记录 FTP 文件信息、操作历史、版本标记等核心数据，为所有模块提供持久化支撑。

# 数据持久化
📂
Windows 控制端

收集模块

根据不同的环节，自动收集整理必要的依赖项，上传至 FTPS 共享存储中，供外包人员下载使用。

# 素材准备
👁️
Linux 服务

版本监控模块

无限循环进程持续扫描 FTP 存储空间 & 服务日志，对每一次文件变更事无巨细地打标记到数据库——谁上传的、多大、是否覆盖、删除等，自动推进版本号（v001 → v002）。

# 全量审计
🔐
Windows 控制端

权限分配模块

用户管理与实时权限控制。新增外包商时自动在 Shotgun 创建用户、同步 Linux 账户到 FTP，自动生成密码并通过钉钉发送连接信息。

# 账号生命周期
🔀
Linux 服务

行为分配模块

监听数据库变化，整合分辨哪些改动属于同一次、哪些是他人同时修改，按环节分类整理。待全部改动完毕，将环节行为命令 + 文件信息发送给自动行为模块。

# 智能路由
🤖
Linux 服务

自动行为模块

按环节执行 TD 编写的自定义检查代码：路径规范校验、帧率/帧数检查、自动发布 Daily & 下游、钉钉通知。提供队列 + 农场节点机制，耗时任务扔到农场分布式执行。

📋 制片添加外包商 & 分配权限

制片在 十月盒子 中打开权限分配工具，添加外包商并指定其可查看/下载的文件范围，系统自动创建账户并发送钉钉通知。

权限分配模块

02

📦 制片收集资产 & 发送至 FTP

制片在十月盒子中使用资产收集工具，半自动找到所有参考数据。点击确定后，工具自动将收集的数据发送至 FTP 存储路径下。

收集模块

03

🔁 外包商按规范回传审核数据

外包商制作完毕后，按照不同环节的路径规范向 FTP 中回传审核数据（含 manifest.json 等必要信息）。

外包商操作
↓
04

🔍 自动监测 → 分配 → 检查

版本监控模块识别新文件 → 行为分配模块等待上传完毕并打包信息 → 自动行为模块识别环节，按 TD 指令开始检查并发布。

全链路自动
↓
05

⚠️ 异常处理：检查不通过

程序运行错误 → 钉钉通知 TD 报错内容。
文件检查错误 → 钉钉通知外包商审核不通过及原因，同时通知相应环节制片。

异常分支
↓
06

✅ 重新回传 & 检查通过

外包商修正后重新向 FTP 回传 → 自动流再次进入 自动行为模块 检查。通过后通知制片，按需发布至 Shotgun，同时向外包商提示回传成功。

外包商操作 全链路自动
↓
07

🚀 最终发布 & 通知

外包商提交最终工程文件 / 数据缓存 / 预览图片等。系统根据 manifest 信息触发自动发布下游程序，使用 CLI 全自动检查发布。无论成功与否，均通过钉钉通知外包商和制片。
