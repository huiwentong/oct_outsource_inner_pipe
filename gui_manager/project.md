# project信息

这个项目主要目的是构建两个独立的GUI应用：collector和usermanager。

主要是使用python和PySide6为基础技术栈。

其中ui文件夹里放着关于PySide6的核心代码

utils文件夹里放着的是两个GUI应用能够通用调用一些基础逻辑：比如说查询数据库，向FTP传输文件，或者调用服务器的一些通用服务请求等等

components文件夹里放着的是对应各个环节要针对collector工具提供的具体能力模块，比如说collector选择了mod环节要执行哪些操作，collector选择了tex环节要执行哪些操作等等

其中服务器的一些基础配置和信息都会放在server_config.yml中

## collctor工具描述

    collctor工具主要是用于制片使用此工具来对不同制作环节的制作文件来进行自动抓包数据并传输到ftp的对应路径中。

    collector工具的界面设计需要偏现代化一些，简约美观，界面尽可能减少不必要的冗余，核心诉求是易于理解方便使用，所有控件布局要符合一个普通非专业人的使用思维

### collector工具设计流程
    所有UI的伊赖数据抓取和后台逻辑全部暂时使用mock数据，这块的逻辑获取我会自己后续补充
- 首先打开工具后首先必须要先选择使用哪个项目(mk2, mko)
- 选择项目后会有三个区域
- 第一个是选择实体/资产区域，来选择（多选）需要要抓包的资产，在这个区域旁边，会有一个补充需要抓包这个资产的哪些环节的多选项（mod、tex、rig、lay、ani、cfx、efx）且环节是必选的，否则数据进入不了第三个区域
- 第二个是选择这些抓包数据要发给哪些外包方，提供一个下来菜单，同时也可以进行输入和自动补全进行选择
- 第三个区域是补充资料区域，这个区域会将所有第一个区域所选择的资产/实体 + 环节（每一个资产/实体都对应着多个环节）都列出来，并自动加载这个环节（对应着components里的具体实现，暂时先使用mock数据）用来补充额外数据的ui控件排在每行后面
- 最后这个工具会提供一个'开始抓包'的按钮，当检查以上信息无误后点击开始抓包再执行相应的具体逻辑，这块先不用实现具体逻辑，加一个打印信息即可

## usermanager工具描述

    usermanager工具是用来向数据库和ftp中新增外包方用户，并创建相应的密码和赋予相应的权限的

    usermanager工具的界面设计需要偏现代化一些，简约美观，界面尽可能减少不必要的冗余，核心诉求是易于理解方便使用，所有控件布局要符合一个普通非专业人的使用思维

### usermanager工具设计流程
    所有UI的伊赖数据抓取和后台逻辑全部暂时使用mock数据，这块的逻辑获取我会自己后续补充
- 这个工具很简单，打开工具有填入几个必要信息然后点击执行即可
- 这个工具必须填入 name: str，
    description: str，
    ding_id: str，
    email: str，
    password: Optional[str] = None
    这几个字段，启动最后的password为选择填入
- 因为这个工具很简单，所以使用说明对这个工具来说很有必要，在每一个必填参数后面都需要跟上具体用途说明，其中password需要补充说明：password为选填，如果不填写此信息，系统会随机生成password
- 这个工具开启后首先需要校验使用者权限，如果检测使用者没有权限则会弹窗提示并自动关闭
- 这个工具点击执行按钮后会在数据库中进行逻辑执行，工具会等待执行反馈，如果成功则会弹窗提示，并重置所有输入，如果失败则会弹窗显示报错并保留当前状态。
- 需要为这个工具预留一个执行成功后继续执行的一个函数，暂时随便打印个信息即可
